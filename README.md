## 一、这个 skill 解决什么

面向互联网 / IT 外包从业者的劳动争议，把"被退项、被待岗、被降薪、被零补偿清退"变成一张**可以核对、可以提交、可以谈判**的清单。

**覆盖的 10 项主张**

| # | 项目 | 定性要点 |
|---|---|---|
| 1 | 违法解除赔偿金 **2N** | 退项/外包/降本 ≠ 客观情况重大变化 |
| 2 | 经济补偿 **N** | 协商解除、40 条、38 条被迫解除 |
| 3 | 代通知金 **+1** | 40 条解除且未提前 30 天书面通知 |
| 4 | 待岗工资/生活费差额 | 第 1 周期全额，之后最低工资 80% |
| 5 | 单方降薪差额 | 未经协商无效；N 的基数仍按降薪前算 |
| 6 | 加班费 | 150% / 200% / 300%，举证责任倒置 |
| 7 | 未休年休假 300% | 补 200%，时效 1 年，只可倒推约 2 年 |
| 8 | 年终奖 / 十三薪 | 指导案例 183 号，按在职月数折算 |
| 9 | 社保基数差 | 行政追缴（税务/稽核），不属仲裁受案范围 |
| 10 | 公积金追缴 | **无时效**，可溯至入职首月，可法院强制执行 |

外加：**换签主体工龄合并**（司法解释二第 3 条）、**混同用工甲方连带**、**竞业限制**、**假外包真派遣**。

## 二、执行流程

```
S0 紧急止血（48h）   → 别签字、先固证（个税/社保/公积金/工资流水/考勤录屏）
S1 八维问诊          → 签约主体/实际管理方/用工性质/退项待岗/解除过程/工资结构/社保公积金/时间线
S2 定性              → 告谁？ N/N+1/2N？ 勾选哪些主张？
S3 算账              → scripts/calc.py 输出清单 + 保守/合理/激进三档
S4 定路线            → 监察 12333 + 税务 12366 + 公积金 12329 + 仲裁 + 保全
S5 出文书            → 异议函 / 催告函 / 被迫解除通知书 / 仲裁申请书
S6 谈判与执行        → 开口激进档，落点合理档，底线保守档；钱到账才签字
```

## 五、已知的模型简化（使用时请注意）

| 项目 | 简化之处 | 实际口径 |
|---|---|---|
| 待岗工资差额 | 按整月或整天数折算 | 法院常**酌定**取中间值；输出已给出"不合法/合法"的区间 |
| 公积金、社保补缴 | 按你填的基数与比例估算 | 受各市**基数上下限**、比例、补缴起始月约束，以中心核定为准（可用 `base_cap` 传入上限） |
| 加班费 | 按你填的小时数 | 举证是最大变量，把握度标为 ★★★ |

## 五、三条最容易被忽略、但最值钱的点

1. **待岗/降薪当月就要发书面异议函** —— 没有这一步，后面"被迫解除拿 N"很可能不成立
2. **公积金追缴没有时效、可以强制执行** —— 外包公司普遍按最低工资缴或不缴，工作 3~5 年的人这一笔常在 **2 万~10 万**，且钱进自己的公积金账户
3. **社保和公积金不能写进仲裁请求**（不属受案范围），必须走行政投诉 —— 但它们是**最有力的谈判筹码**：公司补缴 + 滞纳金 + 罚款可能远超你的赔偿金
